## `migrate` refuses a plan the database has moved away from; `status()` supersedes resolved failures (#739)

- **Version**: Unreleased
- **Recorded**: 2026-10-01
- **PormG ref**: #739; `src/migrations/runner.jl` (`migrate`, `status`, `MigrationStatus`, `PlanPreconditionError`), `src/migrations/planner.jl` (`makemigrations`), `src/Generator.jl` (`generate_migration_plan`)
- **Severity**: behavior change. A plan generated by an earlier PormG has no precondition and applies exactly as before; `MigrationStatus` gains a field.

### What changed

**The plan records the schema it was generated against.** `makemigrations` writes one header
comment per table its diff compared, a fingerprint of that table or `absent`:

```
# pormg-schema-table: 3f9a1c0e7b2d4a51	circuits
# pormg-schema-table: absent	driver_standings
```

`migrate` reads the same tables again before any statement runs — once before the migration lock,
and again inside it — and throws the new `PormG.Migrations.PlanPreconditionError` (a
`MigrationError`) when any of them differs. None of the plan's statements runs, and no `failed` row
is recorded. Before, the plan ran against whatever schema it
found: half-way on a database it was not generated from, or again, as an old release's plan, after a
newer one had moved past it. The header is a comment, additive within migration format v1 and
outside the checksum.

**`status().failed` no longer lists a failure a later apply resolved.** A `failed` row whose plan
(the same checksum) a later run applied is in the new `superseded` field instead, and the
"N failed migration(s)" drift signal counts only the unresolved ones. Nothing changes in the
`pormg_migrations` table itself: `superseded` is how `status()` reads it.

`MigrationStatus` gains `superseded` as its third field, so code that constructs one positionally
needs the extra argument.

### How to find the calls to migrate

```bash
grep -rnE 'MigrationStatus\(|\.failed\b|pormg-migration-format' --include=*.jl .
```

### Migrate your app

```julia
# before: every failed attempt, including ones a retry resolved
st = PormG.Migrations.status("db")
length(st.failed)

# after: only the unresolved ones; the resolved ones are in `st.superseded`
length(st.failed)
length(st.superseded)

# before
PormG.Migrations.MigrationStatus(applied, failed, pending, has_table, signals)
# after
PormG.Migrations.MigrationStatus(applied, failed, superseded, pending, has_table, signals)
```

A deploy that applies a reviewed plan needs no change. If `migrate` now refuses a plan because
production was changed by hand on purpose, regenerate the plan against that database with
`makemigrations()`, or delete its `# pormg-schema-table:` lines to apply it without the check.
