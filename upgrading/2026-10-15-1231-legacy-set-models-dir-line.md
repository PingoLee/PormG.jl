## Generated model files — delete the legacy `Models.set_models(@__MODULE__, @__DIR__)` line (#1231)

- **Version**: 0.9.0
- **PormG ref**: #1231 ; `src/Generator.jl` (no longer emits it), `src/Models.jl` (`set_models`)
- **Recorded**: 2026-10-15
- **Severity**: behavior change. Nothing changed in this release for this line itself; the
  registration it performs now refuses an unloaded folder (#1226), so a file that still carries it
  fails where it used to load the folder quietly.

### What changed

Model files generated by older PormG versions end with:

```julia
Models.set_models(@__MODULE__, @__DIR__)
```

The generator stopped emitting it long ago, and `@import_models` registers the module itself. A
file that still has the line, loaded through `@import_models`, registers the module **twice**. The
first registration runs inside the `include`, before the macro's own, and binds against the
folder's absolute path.

| | before | after |
|---|---|---|
| the line, folder loaded first | two registrations of the same module; harmless, wasted work | the same |
| the line, folder not loaded yet | the first registration loaded the folder implicitly — environment from `PORMG_ENV`/`default_env:`, key = the absolute path | `InvalidConfigurationError` from inside the `include` (#1226); in a REPL, the implicit load with its warning |

### How to find the calls to migrate

```bash
grep -rn 'set_models(@__MODULE__, @__DIR__)' --include='*.jl' .
```

### Migrate your app

```julia
# ✗ before — the last lines of db/models.jl
Result = Models.Model("results", resultid = Models.IDField(), points = Models.FloatField(null = true))

Models.set_models(@__MODULE__, @__DIR__)
end

# ✓ after — delete the line; `@import_models "db/models.jl" models` registers the module
Result = Models.Model("results", resultid = Models.IDField(), points = Models.FloatField(null = true))
end
```
